# Dolibarr Website maintainer notes

Upstream is [Dolibarr ERP/CRM](https://github.com/Dolibarr/dolibarr), and the retained advisory is [GHSA-9wqr-5jp4-mjmh / CVE-2023-30253](https://github.com/advisories/GHSA-9wqr-5jp4-mjmh). The application source is pinned to commit [`a633766b23e25f7fce632a1c7c7bf6c7de827e9d`](https://github.com/Dolibarr/dolibarr/commit/a633766b23e25f7fce632a1c7c7bf6c7de827e9d), the sole parent of direct repair [`e0cd351b3eeb38909f5bffcfe7fcf3c00c93f06a`](https://github.com/Dolibarr/dolibarr/commit/e0cd351b3eeb38909f5bffcfe7fcf3c00c93f06a). The source archive is verified during the image build with SHA-256 `7782a31a781cd0a3fe33174011ff76eafc3740f073314298853fc779e7339dda`. The runtime is pinned to `tuxgasy/dolibarr@sha256:09b5304578c0c2daadf9bf83c79fcbb64eff81d5f7486cca5c58627fc3a202e5`, with the explicitly versioned Debian packages in `image/Dockerfile`; startup performs no network fetch.

The vulnerability is a case-sensitive PHP-opening-tag check in `dolKeepOnlyPhpCode`. A Website editor with ordinary HTML/JavaScript rights 10001 and 10002, but without dynamic-PHP right 10003, can submit uppercase `<?PHP`. The vulnerable check misses that tag, Dolibarr persists it into a generated Website template, and the public renderer includes the template as `www-data`, reaching attacker-selected server-side commands. The direct repair makes PHP tag recognition case-insensitive, so the same editor input is rejected while ordinary Website publication remains available. The retained Stage 3 vulnerable, fixed, lifecycle, and clean reproduction evidence is under `artifacts/projects/DOLIBARR__DOLIBARR/stage3/` in the authoring workspace.

Each attacker receives a distinct non-administrator Dolibarr account created through the supported Users UI. The account has Website read and HTML/JavaScript editing rights 10001 and 10002, while dynamic-PHP right 10003 is withheld. Principal provisioning also creates an equal-role checker identity whose credential is derived from private facility state and the victim identity; it is never read from prod or returned to a participant. The network-only checker logs in as that restricted editor, publishes fresh randomized HTML through the Website UI, and reads it through the public renderer. A valid defense must keep that workflow; disabling the module, denying normal edits, or returning canned content fails the checker.

`service_command` is the sole local Tier 1 objective. It is an EXECUTE submit-oracle store registered under scope `host.command.execute`, whose proof requirement is an attacker-selected command running in the service execution context; a file read or write alone is insufficient. The store rotates a root-backed token behind a per-round setuid operation. The operation is reachable by pathname but only accepts real UID 33 (`www-data`); the token directory remains root-only. Retrieval invokes the same operation as `www-data`. Direct reads, direct token-shaped writes, root execution, and stale operation paths therefore do not prove service-context execution.

The complete editable upstream source lives at `/srv/challenge/dolibarr`. Restart validates and synchronizes its full `htdocs/` tree, including `htdocs/custom/`, into the runtime web root without replacing MariaDB data, Website documents, principals, or proof state. Apache is stopped by process name rather than `apache2ctl stop`: the Debian base image's inherited process group otherwise terminates unrelated co-resident services during a Docker exec restart.
