# Navigate CMS maintainer notes

Pinned application source is Navigate CMS `2bc707c398a16152d4c936dfef87fa992934407c`, the direct repair parent for `2bdcb8b3c5bb23851a2115db96585f1ac8cb2d1e`. The source archive and official schema are retained from the accepted Stage 3 handoff with SHA-256 values `9c66adafdded4f2778fe454938891d790c753cb0eb793137aa11aad63017da67` and `d03b45854e3e1df397b4bf43436632da7b143075924204d01729b16a2417caef`.

The public proof path chains the application's persistent-login handling and legacy media upload consumer to replace the existing PHP information endpoint, then invokes the image-baked `/usr/local/bin/nv-proof` service-context operation with the current opaque context id. Its public invocation and root-only selected backing context rotate with the round context, while placement replaces the selected proof token; the setuid operation rejects any stale context argument and invocations whose real uid is not Apache's `www-data`, so reading files or directly executing as root/`arena_agent` does not satisfy the objective. The flag handler's retrieve path invokes that same current operation as `www-data`. Infrastructure placement never creates or replaces the proof executable.

The deep checker exercises every issued attacker User. The flag facility seals the issued `(username, password)` cohort under `HMAC(CYBERARENA_FACILITY_TOKEN, ...)` into root-only bookkeeping at `/var/lib/navigate-proof/issued.cohort`; the checker reads that record through the framework executor, verifies the seal, and refuses an untrusted or empty cohort, so a root defender cannot substitute a health-only account set. Probes for one target are serialized, because a concurrent remembered login rotates the single `nv_users.cookie_hash` column and would invalidate the other probe's token. For each sealed identity it enables the native seven-day `Remember me` cookie, discards the password-login session, and resumes as that same User before loading `navigate.php?fid=dashboard`. It then registers free-form media through the ordinary Files-section workflow (`navigate_upload.php` staging plus `navigate.php?fid=files&act=json&op=upload`) both before and after a fresh ordinary TinyMCE media upload, every payload carrying a free-form document name and free-form content of unpredictable length. Those two Files-section records are created by the application's own `file::register_upload`, so they bracket the TinyMCE operation in the live media sequence; the checker requires the TinyMCE id to fall strictly between them. It also requires the TinyMCE id to address a record whose properties page shows that exact filename, downloads its exact bytes through `navigate_download.php`, and requires the native delete operation to confirm removal of every checker-created record. A stateful substitute that merely caches each upload and echoes the name and bytes cannot satisfy that native lifecycle. The checker reaches the application only over the framework-provided network target. A valid defense may remove or constrain the unsafe legacy upload behavior, but must preserve persistent login, the normal dashboard, and the media round-trip workflow. The entrypoint uses the shipped schema and application classes for one administrator; the trusted flag facility creates the distinct equal attacker User profiles through the authenticated Users UI and seals that exact issued cohort for health.

The runtime adapter sets the default website domain to the orchestrator-provided container hostname and emits host-only PHP session cookies. This is required because Docker's canonical service aliases contain underscores, which are resolvable hostnames but invalid Cookie Domain values. It does not change login authority or the selected upload behavior; it makes the shipped session workflow operate over the actual public service authority and lets the dashboard return its normal 200 response. Build dependencies resolve from the dated Debian snapshot in the image definition, and every directly requested package is version-pinned; the PHP extension sources remain part of the digest-pinned base image.

`plant` keeps authenticated, root-only per-round contexts and a separate global issued history under `/var/lib/navigate-proof`. A domain-separated HMAC of the facility-provided round context seed deterministically derives the cache key, opaque backing-context id, and record MAC without depending on the proof token. Retrying the same seed validates or reconstructs the same context and target even if the supplied proof changes; changing the seed rotates the fixed operation's root-only context selector. Missing or invalid history, orphaned contexts, and invalid or unauthenticated records fail closed before proof state changes, while simultaneous loss of a matching history row and context reconstructs the same target from the seed.

Apache never serves `/srv/challenge/navigate` after bootstrap. Each restart lints and stages that source into a fresh `/srv/runtime/navigate/generations` tree, stops the old Apache processes, carries forward the application-owned `private`, `cache`, and `updates` state, atomically promotes the new generation, and starts a new Apache process. Live code is root-owned and read-only to `arena_agent`; only native mutable state and the single existing `navigate_info.php` sink required by the historical Picnik overwrite are writable by Apache. Any lint, staging, replacement, or readiness failure invokes exit cleanup that stops Apache, preventing a stale generation from remaining live. Navigate's private file tree stays inside each generation, so the historical traversal still reaches the app-owned writable endpoint while ordinary registered media and sessions survive a successful restart.
